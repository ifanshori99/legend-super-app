## Temuan

- **P1 — Sesi login baru masih dapat melewati PIN kasir:** `apps/api/src/middleware/auth.ts:27` @ `839500696`; stempel hanya dijalankan oleh `requireAuth`, sedangkan sign-in Better Auth langsung melalui `apps/api/src/app.ts:387` dan hook pembuatan sesi `apps/api/src/lib/auth.ts:553` tidak mengambil perangkat dari header login. **Skenario:** Owner login dengan `X-Device-Token` valid untuk perangkat aktif `shared_mode=true`; sebelum request terautentikasi lain, cookie baru dipakai ke POS tanpa `X-Device-Token` dan `X-Acting-Staff`. Penanda masih `[]`; `apps/api/src/middleware/acting-staff.ts:137` sampai `:146` meneruskan request sebagai owner. **Perbaikan:** Ikat penanda ke sesi ketika sesi diterbitkan dari token perangkat yang diverifikasi, sebelum cookie dapat dipakai. **Usul test:** Sign-in HTTP dengan token perangkat bersama, lalu langsung POST ke operasi POS yang valid tanpa kedua header; wajib `401 ACTING_STAFF_REQUIRED`, tanpa perubahan data atau audit tindakan owner. Sertakan request pertama ke tenant lain milik owner yang sama.
- **P1 — Alias denah outlet melewati guard perangkat bersama:** `apps/api/src/routes/floor.routes.ts:202` @ `839500696`; `outletFloorRouter` belum memasang `resolveActingStaff` dan `requireActingStaffOnSharedDevice`, sementara `floorRouter` sudah memasangnya di `:81`. **Skenario:** Cookie owner yang sudah ditandai shared tetap dapat memanggil `GET /api/outlets/B/floor` tanpa PIN; token kasir outlet A yang dikirim ke alias itu juga diabaikan. Jika owner memiliki izin B, data B terbaca sebagai owner. Ini lolos sampai SQL: `floor-access.ts:123` sampai `:136` menghasilkan scope owner karena `req.actingStaff` kosong, lalu `floor.service.ts:255` sampai `:264` dan `:311` sampai `:319` membaca outlet B dalam scope tersebut; RLS tidak mengembalikan identitas kasir yang tidak di-resolve. **Perbaikan:** Pasang resolver dan guard yang sama pada `outletFloorRouter`. **Usul test:** Cookie shared tanpa kasir wajib 401 pada `/api/floor` dan alias outlet; kasir A ke outlet B wajib ditolak, sedangkan akses kasir A ke A tetap sesuai izin.
- **P1 — Migrasi baru dilewati pada upgrade dari tip m1:** `apps/api/drizzle/meta/_journal.json:2948` @ `83dd3da01` dan `:2976` @ `839500696`; `0495/0496/0545/0546/0560/0561/0575` memakai `when` berurutan `1795000000047` sampai `1795000000053`, sedangkan m1 `0442` sudah `1795000000057`. **Skenario:** DB sudah dimigrasikan sampai tip m1, lalu memakai journal integrasi yang mempertahankan timestamp cabang ini; Drizzle melewati seluruh tujuh migrasi. Tabel ulasan dan kolom perangkat/sesi tidak dibuat, backfill MCP tidak berjalan, dan akses aplikasi baru dapat gagal karena skema belum ada. **Bukti:** `PgDialect.migrate` Drizzle terpasang `0.45.3`, dijalankan dengan stub session berisi `lastDbMigration.created_at=1795000000057` dan empat kandidat asli 981, menghasilkan `executedStatements=0`; jalur produksi memakai migrator itu melalui `apps/api/src/db/migration-session.ts:87`. **Perbaikan:** Rekonsiliasi seluruh entri baru secara monoton terhadap journal target integrasi; menaikkan 0575 saja tidak cukup. **Usul test:** Upgrade DB disposable yang sudah sampai tip m1, verifikasi ketujuh migrasi diterapkan, lalu jalankan ulang dan pastikan tidak ada perubahan data tambahan.
- **P2 — Batas delapan penanda dapat menghilangkan perlindungan perangkat kesembilan:** `apps/api/src/services/shared-device.service.ts:88` @ `839500696`; ketika semua delapan penanda masih aktif, `COALESCE(..., ids)` mempertahankan daftar lama tanpa mencatat perangkat baru. **Skenario:** Satu sesi digunakan pada sembilan perangkat bersama; admin lain kemudian mencabut atau mematikan shared mode delapan perangkat pertama. Perangkat kesembilan tetap aktif/shared, tetapi cookie tanpa header kini lolos karena seluruh penanda tersimpan sudah tidak aktif. Pemeriksaan self-disable juga tidak mengenali perangkat kesembilan bila header dihilangkan. **Perbaikan:** Simpan semua penanda aktif atau simpan status overflow yang tetap menuntut PIN; jangan diam-diam melewatkan penanda baru. **Usul test:** Isi delapan penanda aktif, gunakan perangkat kesembilan, nonaktifkan delapan lama dari sesi admin lain, lalu pastikan POS tanpa header tetap `401 ACTING_STAFF_REQUIRED` dan self-disable perangkat kesembilan tetap ditolak.

## Hasil pemeriksaan lainnya

- Diff 1: Tidak ditemukan kebocoran konkret tambahan pada SQL/RLS `customer_reviews`; helper memasang ENABLE/FORCE dengan kebijakan tenant/outlet restrictive. TL-21 memakai `assertKnownOutlets`, mengecualikan ulasan hidden, dan mengeluarkan agregat tanpa kolom identitas atau teks ulasan. Seleksi 0546 membatasi tenant aktif, entitlement paket MCP, serta klien approved/token aktif; audit dan pengulangan backfill diperiksa secara statis. Jalur bearer, token exchange, dan eksekusi aksi MCP memeriksa modul MCP.
- Diff 2: Tidak ditemukan temuan konkret tambahan. TL-08 jalur manage dan TL-20 memeriksa outlet asing sebelum query; pembatas tenant/outlet tetap ada. Daftar sesi memakai SQL `user_id` dan tenant grant; daftar perangkat menyaring `tenant_id` yang memang dikembalikan fungsi SQL. Grant kosong menutup daftar, dan support DELETE ditolak middleware.
- Migrasi 0575: Nilai `shared_device_id` 0561 disalin ke array sebelum kolom dihapus. Migrator menjalankan perubahan dalam transaksi; tidak ditemukan kehilangan nilai 0561 atau cacat idempotensi tambahan pada jalur migrator normal. Idempotensi SQL mentah di luar migrator tidak diasumsikan.
- Keputusan CTO dalam brief diperlakukan sebagai batas review dan tidak dihitung sebagai temuan.

## Batas bukti dan gerbang

Bukti migrator memakai kode Drizzle asli dengan session stub; itu bukan uji upgrade database. Test integrasi, build, dan gate penuh tidak dijalankan dalam review read-only ini.
