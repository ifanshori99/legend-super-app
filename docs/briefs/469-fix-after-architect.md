Keep `periodMismatch` comparing against `nextPeriodEnd ?? currentPeriodEnd`.
B. `startSubscription` ~:453-465: (1) retrying an EXISTING intent row (provisioning/needs_reconcile found by idempotency key) loads the client with purpose "stop" (any integration status), because the only goal is to learn/tie the provider subscription so it can be cancelled; a NEW intent still requires an active integration (purpose "bill"). (2) a NEW idempotency key while an unresolved row (`provisioning`/`needs_reconcile`, same tenant+plan+customer) exists -> CoreError CONFLICT ("Ada langganan yang belum terkonfirmasi di gateway. Coba lagi dengan kunci yang sama." style, Indonesian), no new row, no DOIT call.
