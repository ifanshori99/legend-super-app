## D1 Scope

Per-order splits only. Target = the session's single `awaiting_payment` order (server finds it; input has no orderId). None (incl. open bill) → `CoreError`/HttpError 422 code `NOTHING_TO_SPLIT`. >1 awaiting → 409 CONFLICT. `order.depositAppliedIdr > 0` → 422 VALIDATION_ERROR. If link exists require `link.totalIdr === order.totalIdr` and `link.paidIdr === 0`.

## Fix round 2 (architect review K findings) — decisions

"Live code" of a part = a payment intent with `bill_split_id = part.id` that is `pending`, OR `expired` with `provider_ref IS NOT NULL` and `expires_at + LATE_PAYMENT_GRACE_MS > now` (a superseded code the gateway may still accept).
R1 `assertSplitMutableTx`: also SPLIT_LOCKED when ANY intent on the order's link (any part or order-level) is `expired` with provider_ref not null and expires_at + grace > now.
R2 (one payable code per part): in `createGuestPayment` split branch, if the part has a live code that is not the same choice (`sameChoice`) → 409 CONFLICT code `SPLIT_CODE_ACTIVE`, message "Kode pembayaran bagian ini masih berlaku; selesaikan atau tunggu sampai berakhir." (same choice → return it, as today). `markSplitPartPaidTx`: on marking paid, also set `payment_intent_id = input.intentId`. When an intent of a part that is already paid by ANOTHER intent (or voided) settles: logger.warn only (no new refund logic; reported as risk).
New helper in bill-split.service.ts: `partLiveCodeTx(tx, context, partId, now): Promise<{ id: string; method: string; channelCode: string | null; status: string } | null>` (newest live code).
R3 voided order: in `voidAndNotify` (qr-order-consumers.ts) call `voidLiveSplitsTx` and new `expireSplitClaimsTx(tx, context, orderId, now): Promise<number>` (bill-split.service.ts: `UPDATE bill_splits SET claim_expires_at = now WHERE order_id = $ AND status='paid' AND claim_redeemed_at IS NULL AND claim_expires_at > now`). `redeemSplitClaimTx`: also require `bill_splits.status = 'paid'` and the order not `voided`.

Add to bill-split.test.ts: R1 re-split refused (409 SPLIT_LOCKED) when the only open code is `expired` with provider_ref set and expires_at in the future (set via owner SQL).
