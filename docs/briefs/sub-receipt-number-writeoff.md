## Why

Since legend-6b0ld, `closePosDay` refuses (`RECEIPT_SEQUENCE_GAP`) while any run of the outlet (idle/revoked device, retired run, cloud seq `C`) has a missing ordinal 1..lastNumber, with no way out. The tenant owner may mark one number (prefix + ordinal) as permanently lost, with a reason; gap checks then count it as present, and reports show it as written off.

## Decided design

### Table `receipt_number_writeoffs` (Drizzle export `receiptNumberWriteoffs`, file `apps/api/src/db/schema/pos-receipt-writeoff.ts`, exported from `apps/api/src/db/schema/index.ts`)

Columns: `id uuid pk` (createUlid->uuid like other POS tables, check pos-receipt.ts), `tenant_id uuid NOT NULL`, `outlet_id uuid NOT NULL`, `sequence_id uuid NOT NULL`, `prefix varchar(12) NOT NULL`, `sequence_number integer NOT NULL` (check > 0), `reason text NOT NULL` (check char_length between 10 and 500), `written_off_by uuid NOT NULL` (user id), `created_at timestamptz NOT NULL default now()`.
Keys: unique (tenant_id, id); unique (tenant_id, sequence_id, sequence_number) name `receipt_number_writeoffs_ordinal_key`; FK (tenant_id, sequence_id) -> receipt_sequences(tenant_id, id) (follow existing composite FK style in pos-receipt.ts, no NOT VALID).
Custom SQL (new fragment `apps/api/src/db/schema/pos-receipt-writeoff.custom.sql`, same text appended to the migration): `SELECT app.enforce_tenant_rls('public.receipt_number_writeoffs'::regclass);` + `app.enforce_outlet_rls(...)` (as pos-receipt.custom.sql does); append-only trigger BEFORE UPDATE OR DELETE (own function `app.receipt_number_writeoffs_append_only()`, `SET search_path = pg_catalog`, ERRCODE 23514, style of `app.pos_receipt_records_append_only`); BEFORE INSERT backstop trigger: refuse when prefix/outlet differ from the sequence row, when sequence_number > sequence.last_number, or when a pos_receipts row exists for (tenant_id, sequence_id, sequence_number) (ERRCODE 23514).
Migration `apps/api/drizzle/0156_receipt_number_writeoffs.sql`: run `pnpm db:generate` from the worktree (generates `0155_*` + snapshot), rename SQL + snapshot to `0156_receipt_number_writeoffs` / `0156_snapshot.json`, set journal entry idx 156, tag `0156_receipt_number_writeoffs`, when `1794235000000` (0155 belongs to the payroll branch; journal skips 155 like it skips 153). Append the custom SQL with `--> statement-breakpoint`. Also add the new permission code to existing tenants' owner template rows, copying `apps/api/drizzle/0104_edc_standalone_permission.sql` (template_key 'owner'). After that `pnpm db:generate` must produce nothing.

### Permission

New code `pos.receipt.writeoff` (tags `["approve"]`) in `packages/shared/src/access/permissions.ts`, POS section with a comment (legend-0hzqw, owner only). Owner template gets it automatically (`catalogWhere(withoutTags("platform","self"))`); do not add it to any other template.

### Gap counting (count write-off as present; mark it)

`apps/api/src/services/pos-receipt.service.ts`:

- `receiptGapsOfRun` and `receiptGapsForOutletFast`: keep the receipt-count fast path unchanged (count == lastNumber => no gap). In the slow path, load the run's write-off ordinals and add them to the present set (pass `[...receipts, ...writeoffs]` to `receiptGaps`). `receiptGapsForOutlet` (non-fast) the same.
- `receiptGapsForDevice`: entry gains `writtenOff: number[]` (ascending write-off ordinals of the run, one query for all the device's runs). An entry is emitted when `missing`, `lost` or `writtenOff` is non-empty.
- Port type `PosReceiptGapRun` in `apps/api/src/services/pos-shift-ports.ts` gains `writtenOff: number[]` (doc comment). Day close keeps checking `missing` only (no closePosDay change).
- Shift report DTO: `packages/shared/src/pos/schemas.ts` `posReceiptGapRunSchema` gains `writtenOff: z.array(receiptNumberSchema)`; `apps/api/src/services/pos-shift.service.ts` maps it with `formatReceiptNumber`.

### Write-off endpoint

- Input schema in NEW file `packages/shared/src/pos/receipt-writeoff.ts`, exported from the pos index: `receiptNumberWriteoffInputSchema = clientInputSchema({ prefix: receiptPrefixSchema, sequenceNumber: z.number().int().positive().max(RECEIPT_MAX_ORDINAL), reason: z.string().trim().min(10).max(500) })` (check how clientInputSchema and other POS input schemas are written; strict). DTO `receiptNumberWriteoffSchema` `{ id, outletId, prefix, sequenceNumber, number (formatted), reason, writtenOffBy, createdAt (ISO) }`.
- Service NEW file `apps/api/src/services/pos-receipt-writeoff.service.ts`, `writeOffReceiptNumber(context, caller, outletId, input)` in `withTenant`: refuse on an edge process (same `isEdgeProcess()` rule as pos-receipt.service.ts; cloud only, CoreError CONFLICT with an Indonesian message); `assertOutletInScope`; lock the sequence row `FOR UPDATE` by (tenant, outlet, prefix) — unknown prefix -> CoreError NOT_FOUND; `sequenceNumber > lastNumber` -> CoreError CONFLICT ("Nomor struk di luar rentang yang sudah terbit."); a receipt exists at that ordinal -> CONFLICT ("Nomor struk ini sudah punya struk."); already written off -> CONFLICT ("Nomor struk ini sudah di-write-off.") (check before insert and map the unique violation 23505 too); insert; `recordAudit(tx, context, {...})` (`apps/api/src/services/core-audit.ts`, example `pos-day.service.ts` ~883-919): action `pos.receipt.written_off`, objectType `receipt_number_writeoff`, objectId the row id, actor the caller, `reason` the reason, maskedChanges after = {outletId, prefix, sequenceNumber, number}, retentionClass `audit_2y`. Return the DTO.
- Route NEW file `apps/api/src/routes/pos-receipt-writeoff.routes.ts`, pattern of `apps/api/src/routes/pos-receipt.routes.ts` (`requireAuth, requireTrustedOrigin, requireTenantContext`, `requireOutletPermission("pos.receipt.writeoff", outletOf)`, `jsonBody`, params/body zod parse). `POST /receipt-writeoffs` -> 201 `{ data }`; also `GET /receipt-writeoffs` (same permission) listing the outlet's write-offs newest first (for the runbook). Mount in `apps/api/src/routes/index.ts` under `/outlets/:outletId/pos` like posReceiptRouter.
