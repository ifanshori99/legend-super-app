## P2/P3 singkat

- **P2 — INSERT posting melewati pemeriksaan jurnal:** `apps/api/drizzle/0642_payout_gl_commit_checks.sql:259`, `:318`; hak INSERT berasal dari `apps/api/drizzle/0348_payout_gl_postings.sql:38`. Penulis SQL `legend_app` dapat membuat posting langsung `kind='settle', fee_posted=true`, nominal positif, sumber bank beku benar, dan key baru tanpa jurnal. Insert guard hanya memeriksa nominal non-NULL dan sumber; tidak ada UPDATE atau INSERT baris jurnal untuk memicu pemeriksaan deferred. Status posting dapat menyatakan jurnal selesai tanpa jurnal. Periksa keadaan akhir INSERT juga, dengan pengecualian eksplisit untuk fee nol. **Usul test:** INSERT sebagai `legend_app` tanpa jurnal harus gagal atomik saat COMMIT; kontrol dengan jurnal principal dan fee yang benar harus berhasil sekali. Jangan menganggap kontrol INSERT yang di-ROLLBACK pada `payroll-payout-900-gl-commit.test.ts:447` sebagai bukti pemeriksaan COMMIT.
- **P2 — Sumber historis cash/non-frozen masih bisa diisi sembarang akun lewat SQL:** `apps/api/drizzle/0642_payout_gl_commit_checks.sql:215`, `:73`. Pada posting cash historis `settle_pending` dengan sumber NULL, penulis SQL dapat mengisi akun B, membuat jurnal Dr payable/Cr B sesuai net, lalu mengubah kind menjadi `settle`; guard mempercayai B yang baru diisi, tanpa membuktikan B adalah kas asal A. Bekukan sumber melalui jalur tepercaya atau tahan saat sumber historis tidak dapat dibuktikan. **Usul test:** pengisian akun selain sumber cash yang terbukti harus ditolak, dan kontrol pada sumber sah hanya menjurnal sekali. Ini sisa batas SQL lama; jalur layanan menolak sumber NULL dan membatasi akun cash.
- **P2 diketahui, dikecualikan CTO:** koreksi palsu melalui role aplikasi tetap kartu `legend-i01jp`; tidak dinyatakan tertutup oleh audit ini. Tidak ada P3 baru yang perlu ditambahkan.
