## Aturan teknis penting

- Tulis ledger hanya lewat `postLedgerEntry` (`services/point-ledger.service.ts`) di bawah `withProfileLock` (`db/member-scope.ts`). Jangan menulis `points_balance`.
- Kedaluwarsa (B13), per profil di bawah kunci. Baris `expire`: `source_type='expiry'`, `reverses_entry_id` = id grant yang kedaluwarsa (ini menautkan expire ke grant), `source_id` = UUIDv5 dari `<grantId>:<n>` dengan `n` = jumlah baris `expire` yang `reverses_entry_id`-nya grant itu + 1. Algoritma: grant = `earn` + `bonus` + `adjust` positif tanpa `reverses_entry_id`; urut `expires_at` naik lalu `id`. `net_i = points_i − Σ|reverse→i|`. `used = Σ|redeem| − Σ restore(adjust positif dengan reverses_entry_id ke baris redeem) + Σ|adjust negatif manual|`. Alokasikan `used` FIFO ke `net_i` (grant tertua dulu); `unused_i = net_i − alokasi_i`. Untuk grant dengan `expires_at <= now`: `sudahKedaluwarsa_i = Σ|expire→i|`; `perluKedaluwarsa_i = unused_i − sudahKedaluwarsa_i`; bila > 0 tulis satu baris `expire` sebesar `min(perluKedaluwarsa_i, saldo_sekarang)`. Saldo tidak pernah negatif. Jalankan ulang tanpa data baru: tidak menulis apa pun.
- `adjust` positif manual tanpa `expires_at` sudah ditolak CHECK `point_ledger_adjust_check`; tes cukup membuktikannya.
- Ulang tahun: profil `membership_status='active'`, consent loyalty aktif (`loyaltyConsentActive`), program aktif, `birth_month_day` = tanggal hari ini di Asia/Jakarta (29 Feb dirayakan 28 Feb pada tahun bukan kabisat), poin = `benefits.birthdayRewardPoints` tier profil (0 atau tanpa tier: tidak menulis). Baris `bonus`, `source_type='birthday'`, `source_id` UUIDv5 `<profileId>:<tahun>`, `expires_at` = sekarang + `program.expiryMonths`.
- Tier: stat jendela = `customer_visits` profil dengan `visited_at >= now − program.rollingMonths` (jumlah `spend_idr` dan hitungan); tier baru = `evaluateTier(aktifTiers, stats)` dari `@starter/shared/crm`. Berubah (termasuk dari/ke null): dalam SATU transaksi update `customer_profiles.tier_id` + `tier_evaluated_at`, insert `customer_tier_history`, dan outbox `tier.changed` (payload `tierChangedPayloadSchema`, lihat cara `appendPointsEvent` di `point-ledger.service.ts`). Tidak berubah: hanya `tier_evaluated_at`, tanpa riwayat. Evaluasi dua kali di periode sama: tidak ada riwayat kedua.
- `tierMultiplierBp(ctx)`: `ctx.profile.tierId` null atau tier tidak aktif atau tidak ada: 10 000; selain itu `benefits.pointsMultiplierBp`.
- Referral (setelah earn pertama, langkah `afterVisit` di `loyalty-earn-referral-step.ts` memanggil `qualifyReferral`): hanya bila program aktif dan `program.referral.enabled`; cari referral `pending` milik `ctx.profile` sebagai referee; order ini harus order lunas pertama referee (tidak ada `customer_visits` lain) dan `eligibleSpendIdr >= minFirstOrderIdr`. Kunci profil referrer SESUDAH referee (kunci referrer: `withProfileLock`). Tolak (status `expired`, tanpa bonus): referrer = referee, referrer bukan `active`, hash WhatsApp referee dipakai profil lain di tenant (status apa pun), atau cap bulanan referrer (`maxReferralsPerCustomerPerMonth`, hitung referral `rewarded` bulan kalender Asia/Jakarta ini) tercapai. Lolos: dua baris `bonus` `source_type='referral'` (referrer `source_id` = id referral, `referee` `source_id` = id order pertama; lewati sisi yang poinnya 0), referral jadi `rewarded` dengan `qualified_at`, `rewarded_at`, `first_order_id` (set `qualified` lalu `rewarded` dalam transaksi yang sama atau langsung `rewarded` dengan ketiga kolom terisi; CHECK kontrak: bukan qualified/rewarded berarti ketiganya NULL).
- Peran: CRUD tier `crm.loyalty.manage` lewat `requireTenantPermission` (lihat `routes/loyalty-program.routes.ts`). Bentuk endpoint: `listLoyaltyTiers`, `createLoyaltyTier`, `updateLoyaltyTier` di `packages/shared/src/crm/endpoints.ts` (sudah ada, jangan ubah). Tier tidak dihapus (nonaktifkan).
- Berkas registri (hanya engineer yang menyentuh): `db/schema/index.ts`, `routes/index.ts`, `worker-main.ts`, `packages/shared/src/crm/*`, `access/*`. Potongan lain: jangan.
