## Schema contract (S1 writes, S2/T rely on these names)
`payment_recurring_subscriptions` (Drizzle `paymentRecurringSubscriptions`):
- `status` CHECK gains `'provisioning'` and `'needs_reconcile'`.
- `providerSubscriptionId` becomes NULLABLE; CHECK: `provider_subscription_id IS NOT NULL OR status IN ('provisioning','needs_reconcile')`. Unique `(tenant_id, provider_subscription_id)` stays.
- `startIdempotencyKey` varchar(200) null, partial unique `(tenant_id, start_idempotency_key) WHERE start_idempotency_key IS NOT NULL`.
- `reconcileReason` varchar(100) null.
- `nextPeriodStart`, `nextPeriodEnd` date null: both null or both set, end > start.
`gateway_webhook_events` (`gatewayWebhookEvents`): add `verifiedIntegrationIds` uuid[] NULL (`verified_integration_ids`): ids of every integration of the tenant whose (current or in-grace previous) secret equals the secret that verified the event, plus the integration that matched. Written ONLY for recurring invoice events at receipt. Nothing else about that table changes.
Migration: temporary number 0290, tag `0290_recurring_reconcile_binding`, journal idx 251 (after idx 250 = 0285), `when` greater than the previous entry. Additive only (ALTER TABLE ADD COLUMN, drop+recreate the two CHECKs, new partial unique index). No new tables, so no RLS lines.

## Service/API contract
- `RecurringClientLoader(context, outletId, integrationId?, purpose?)`: `purpose: "bill" | "stop"` (default "bill"). "bill" (start, resume): integration found by id MUST have `status === "active"`, else CoreError SERVICE_UNAVAILABLE (item 1). "stop" (pause, cancel): `loadIntegrationCredentialsById(..., { forStoredIntent: true })` (item 2); any status allowed.
- `InvoiceEventOptions`: remove `integrationAccepts`; add `acceptedIntegrationIds?: string[]` (computed by the webhook layer BEFORE the transaction; the service does no DB/network work for it under the FOR UPDATE lock). Accept when `verifiedIntegrationId` or any `acceptedIntegrationIds` equals `subscription.gatewayIntegrationId` (case-insensitive); else INTEGRATION_MISMATCH (item 5).
- `processDoitInvoiceEvent` result adds nothing new; `unknown_subscription` for a subscription whose row has provider id null stays unknown (it is not matchable yet).
- Exports added by S1: `subscriptionHasAccess(subscription, now): boolean` (status `active` AND today (Asia/Jakarta business date) inside `[currentPeriodStart, currentPeriodEnd)` OR inside `[nextPeriodStart, nextPeriodEnd)`), and `promoteDueSubscriptionPeriods(context, now): Promise<{ promoted: number }>` (moves next period into current when `nextPeriodStart <= today`, sets `active` for live statuses (pending_first_payment/active/past_due) if that period covers today, clears next; never touches paused/cancelled/needs_reconcile/provisioning). `getSubscription` promotes a due next period of that one row lazily.
- Export added by S2: `reprocessParkedRecurringEvents(context, now, opts?: { providerSubscriptionId?: string; limit?: number }): Promise<{ checked: number; processed: number }>`. S1's route `POST /payments/recurring/subscriptions` (start) calls it best-effort (try/catch, log) with the new subscription's provider id after a successful start.
