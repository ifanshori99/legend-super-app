## Interfaces to build (fixed names so tests and code meet)

1. `services/edge-selfie-unseal.ts`: `loadSelfieSealKeys(env = process.env)` reads `ATTENDANCE_SELFIE_SEAL_KEYS` (JSON `{kid: PKCS#8 PEM}`) lazily per call; `unsealSelfie(sealed: Buffer, keys): {header, meta, webp}`; throws `SelfieUnsealError` (maps to 422). Never log key material or plaintext.
2. `services/edge-selfie-link.ts`: `linkEdgeSelfie(tx, {tenantId, objectId}): Promise<"linked"|"already"|"waiting"|"unlinked">`. Takes `pg_advisory_xact_lock(hashtextextended('attendance-selfie-link:<tenant>:<objectId>', 0))`; finds object (`core_storage_objects.id = objectId`) and log (`attendance_logs.photo_key = objectId`); both exist: savepoint, `linkStorageObjectSource(sourceKind 'attendance', sourceId ulidToUuid(log.id), actorUserId = log employee's user_id, outletId = log.outletId)`; on any failure rollback savepoint, set log `photo_key = NULL`, add flag `selfie_unlinked` (keep review pending), warn log ids only. Never throws for link failures.
3. `services/edge-selfie-receive.ts`: `receiveEdgeSelfie(deps {database, storage, scanner, now?}, node: VerifiedEdgeNode, input {objectId, body: Buffer, sealedSha256Header}): Promise<{status: 200|201}>`; throws `HttpError`/`CoreError` for 400/403/409/413/422/503 per design 6.1 (codes `OBJECT_ID_TAKEN`, `SELFIE_SEAL_KEY_MISSING`...). Order: header sha mismatch 400; no keys configured 503; advisory lock `edge-selfie:<T>:<objectId>`; receipt exists: `discarded` -> 200 without writing, same hash 200, other hash 409; object row without receipt 409 OBJECT_ID_TAKEN; unseal (422); header.tenantId == node tenant and header.objectId == path else 403; meta.outletId == node outlet else 403; ownerUserId must be `employees.user_id` of the tenant else 403; `processImage` then S3 put `${objectId}/original.webp` + `${objectId}/thumbnail.webp`; insert `core_storage_objects` (id = objectId, purpose 'selfie', private, source kind 'attendance', sourceId null, owner = ownerUserId, outlet = O) + receipt `stored`; then `linkEdgeSelfie`. DB access via `withTenant` with the node's outlet scope.
4. `routes/edge-selfie-receive.routes.ts`: `createEdgeSelfieReceiveRouter({database, storage|null, scanner, perIp?, perNode?, windowMs?, now?})` exposing `PUT /:objectId`; same pre-auth limiter pattern as `routes/staff-pin-sync.routes.ts`; auth with `verifyEdgeCredential`; body `express.raw({type: () => true, limit: EDGE_SELFIE_SEALED_MAX_BYTES})` (413 over limit); no storage runtime -> 503. Mount in `routes/storage-api.routes.ts` at `/edge-sync/attendance-selfies` (path filtered, like the /storage/ filter) so it gets `runtime.storage` and `runtime.scanner`. No change to EDGE_API_PREFIXES (cloud only by default).
