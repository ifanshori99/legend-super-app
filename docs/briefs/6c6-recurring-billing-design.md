## Money invariants ("jangan sampai rugi")
- Plan price is server truth (`plans.amount_idr`). Invoice amount in webhook that differs from plan price: store invoice with status `needs_review`, `review_reason='AMOUNT_MISMATCH'`, NO notification, NO activation on paid.
- Subscription becomes `active` ONLY from a verified `invoice.paid` event where payload status = 'paid', amount == stored invoice amount == plan price, invoice status was 'open'. Never from `invoice.created`, never from API calls. First invoice paid => pending_first_payment -> active, period set from invoice period. Later paid invoice => period advances, past_due -> active.
- Webhook signature already verified by `receiveDoitWebhook` before dispatch; reuse. Idempotent: store-then-process, dedupe per event id (existing `gateway_webhook_events`), plus unique keys above; replay of same invoice.created must not double-notify (`notified_at` set once, in the same tx as the outbox row); replay of invoice.paid must not double-advance period.
- Cross-tenant: tenant derived from webhook URL/secret, subscription lookup by `(tenant_id, provider_subscription_id)`; unknown subscription => event marked failed/ignored with code, no row created.
- Paused/cancelled subscription: invoice.created stored but not notified; invoice.paid on cancelled subscription => `needs_review` (money received, no access), never reactivates.
