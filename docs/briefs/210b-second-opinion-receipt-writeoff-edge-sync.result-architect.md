## Jawaban pertanyaan
1. Nomor dihitung ada padahal masih bisa terbit: tidak ditemukan. Edge menyalin hanya bila run lokal `last_number >= n` dan tidak ada struk lokal. Alokasi edge gapless dalam satu transaksi (UPDATE last_number + INSERT struk), merge perangkat hanya maju atas run lengkap; READ COMMITTED membuat alokasi yang belum commit terlihat sebagai `last_number` lama (dilewati). Restore DB: write-off dengan n di atas counter hasil restore dilewati; struk terbit ulang membatalkan salinan (notExists). Rotasi zsdd / heal hfq3z / pensiun sduiq: write-off terikat id run; run pensiun lokal tetap cocok dan tidak bisa menomori lagi. Trigger 0156 menjadi backstop.
2. Isolasi: cloud membaca dengan `withTenant` + filter tenant dan outlet dari node terverifikasi (edge-device-sync.ts:396-447). Edge: outlet dari konteks, baris outlet lain menolak seluruh daftar, run dicari per tenant+outlet, insert di bawah RLS outlet. Tidak ada FK `written_off_by`, jadi user cloud yang tidak ada di edge tidak memutus insert. Aman.
3. Idempoten: set `present` + `onConflictDoNothing` + kunci ordinal. Di atas 1000: 1000 terbaru dikirim; DB edge baru hanya memegang run baru, jadi yang tertinggal hampir pasti run yang tidak dipegang (fail closed). Baris rusak / galat non-23514: seluruh daftar ditolak, pull jalan terus. Galat baca cloud: savepoint, field tidak dikirim.
4. Kompat: edge lama tidak meminta field. Edge baru + cloud lama/rollback: 400, ulang tanpa `receiptWriteoffs`, lalu rantai lama. Urutan cloud dulu benar.
5. Halaman ganda: diterapkan sekali, sesudah sequences halaman itu. Rantai 400: hanya percobaan pertama yang membawa parameter.
